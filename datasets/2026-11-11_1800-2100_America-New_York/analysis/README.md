# 11 月 11 日晚间 BDFM 数据分析

这批数据覆盖 **2026 年 11 月 11 日纽约时间 18:00–21:00**，每 30 秒采集一次。它支持下一步构建 ETA 误差预测的数据流程：采集完整、能连接预测与候选到站、也能获取官方延误和改道信息。到站时间仍是 API 推断，训练标签需要核验；本批尚不能证明模型能预测真实延误或换线收益。

## ETA 偏差怎样计算

**偏差估计 = API 推断到站时间 − 此前预测的到站时间。** 正值表示比该次 ETA 晚，负值表示更早；单位为分钟，不是相对计划时刻表的延误。

参考预测选取本次采集中最早符合条件的一条：显示还有 4–6 分钟到站、早于候选到站观测区间，并通过源时间检查。不同记录的预测剩余时间并不完全相同；出现大幅修订时，参考预测与候选到站之间可能远超 6 分钟。

候选到站要求车站位置前进、车辆时间更新、剩余停靠列表一致。车辆时间戳未必就是精确物理到站时间，因此下表统一称为偏差估计。

| 全部 1,060 个匹配样本 | 结果 |
|---|---:|
| 平均带符号偏差 | +0.32 分钟，约 +19 秒 |
| 偏差中位数 | +0.13 分钟，约 +8 秒 |
| 平均绝对偏差 | 0.86 分钟，约 51 秒 |
| 比参考 ETA 晚的样本 | 591 / 1,060，55.8% |
| 比参考 ETA 晚超过 1 分钟 | 209 / 1,060，19.7% |
| 比参考 ETA 晚超过 2 分钟 | 75 / 1,060，7.1% |
| 带符号偏差第 90 百分位 | +1.67 分钟 |

这批结果提示：总体平均偏差不大，但存在较长等待的尾部。展示时宜同时给出样本数和“晚超过 1 分钟的比例”，避免只用平均数。每个样本是一个车次×方向站点，同一车次在多站出现，不能当作彼此独立的乘车经历。

| 事件 | 本次看到通知的范围 | 通知内容 |
|---|---|---|
| Queens Plaza 信号问题，275879 | 18:00:02–20:16:02 | E/F 延误；部分南向 F 经 Roosevelt Island 或 G 线改道，随后出现恢复正常停靠及剩余延误通知 |

“Express to Local”属于第二个事件的状态变化，不是第四起事件。另外两个 `Planned - Reroute` 事件在本轮观测时间未生效，不能计作当时正在发生的改道。实际临时改道也可能写在 `Delays` 通知的正文中，因此只筛选标题类别包含“Reroute”会漏信息。

官方通知涵盖全线，包含曼哈顿研究范围之外的故障。线路与时间重合可以提供模型特征，但不能直接证明该事件造成某一车次的偏差。[去重事件及原文](official_events.json)

## 需要复核的标签

对参考预测至候选到站之间的车辆轨迹增加检查后，**7 个样本**被标记：6 个跨越非预期站点跳转，另 1 个跨越超过 90 秒的观测缺口且出现重复站点。这些是复核提示，不自动认定数据错误。

最大偏差记录是 D 北向 Herald Sq：19:20:28 的预测给出 **19:25:45** 到站，候选时间为 **19:40:21**，相差 **14.6 分钟**。但同一车次标识在 19:20:28 至 19:32:28 之间缺少车辆观测，站点从 Broadway-Lafayette 回到 Grand St 后再次前进。因此参考预测与后续车辆状态是否对应连续可靠的轨迹，需要进一步确认。这条记录不宜直接展示成“真实延误 14.6 分钟”。

排除全部 7 个标记样本后，剩余 1,053 条的平均偏差为 **+0.30 分钟**，晚超过 1 分钟的比例为 **19.4%**，最大偏差估计为 **6.13 分钟**。整体判断变化不大，但最大值明显变化。未触发标记也不代表已经核验。

此外，3,901 个至少有两次预测的车次×方向站点组合中，2,172 个出现 ETA 变化（55.7%）。最大的变化范围为 32.13 分钟，来自同一个异常轨迹的 D 车次。这里的范围是最大 ETA 减最小 ETA，既可能上调也可能下调，不能称为真实延误。

## 对训练算法的意义

已生成 [1,060 条候选训练样例](training_examples_unvalidated.csv)。每行对应一条参考预测及后续候选到站，保留以下内容：

- 输入示例：预测被采到的时间、线路、方向、站点、源时间对应的预计等待时间、此前最多 60 秒内可见的 ETA 修订，以及当时已经下载到的线路级有效通知。
- 候选目标：API 推断到站相对参考 ETA 的偏差分钟数。它是可正可负的预测误差，不是官方延误分钟数。
- 复核信息：车次标识、参考预测和候选时间、轨迹标记；所有行均标为 `label_validated=False`。

通知特征按下载完成时间做向前匹配，不使用之后发布的通知。`eta_revision_within_prior_60s_min` 比较参考 ETA 与此前 60 秒内最早可用的 ETA；缺少历史时留空，并非保证恰好相隔 60 秒。通知只匹配线路，不保证影响该站该方向；无可用通知快照时源年龄为空。

`event_hour_local`、`candidate_arrival_local`、`eta_error_proxy_min`、轨迹复核标记等使用事后信息，只供标签或分析，不能当作实时预测输入。按到站小时汇总也不能替代按预测时刻建立训练特征。

下一步先核验少量真实到站与这些候选时间是否一致，再增加其他日期和时段。建模时按车次、日期分组切分训练与验证，避免同一车次不同站点进入两边；这三小时的数据不足以独立证明跨日期预测能力。当前标签偏向能被成功跟踪且有合适参考 ETA 的样本，尤其需要检查长延误或改道是否更容易漏掉。

## 文件与复现

原始数据保存在上一层的 `collection.tar.xz`，数据库及原始响应保持原样。SQLite 完整性检查通过，归档中 739 个文件的大小与 SHA-256 均与 `source_manifest.json` 一致。

从仓库根目录运行以下命令，将 `RUN_DIRECTORY` 换成归档解压后的原始运行目录，即可在新目录重算派生 JSON 和 CSV：

```sh
python3 scripts/analyze_collection.py RUN_DIRECTORY /tmp/mta-analysis
```

脚本只读源数据库，校验每个标签的参考预测和偏差计算。报告中的比例按样本计数，均值直接汇总样本；百分位采用线性插值。全部 1,060 条的统计与排除标记后的敏感性结果分别保存在 [analysis_summary.json](analysis_summary.json)。
